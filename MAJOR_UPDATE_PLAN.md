## Goal and observable finish line

Build a dependable, low-gesture, two-hand desktop controller: the primary hand points and deliberately clicks; the secondary hand offers controlled volume/zoom; paired hands can switch tabs; custom cinematic gestures can be previewed and later bound to safe actions. Face/background false detections must not move the cursor or inject OS input. The UI must explain *what was seen*, *what was accepted*, *what was rejected*, and *what action would/will fire*.

**Release gate:** Eli can perform the scenario checklist in the final phase with no unintended OS action, no stuck mouse button, usable responsiveness on his laptop, and a clean camera/UI shutdown. Automated tests, replay tests, and the manual acceptance session must all pass; a green unit suite alone is insufficient.

## Thin v1 and exclusions

The **first usable checkpoint** is Phases 0–4: backed-up, false-positive-safe, preview-first pointing plus deliberate left/right click. Ship and test that independently before enabling dual-hand actions. Phases 5–10 build the rest of the major update behind separate feature flags and acceptance gates; this is not one giant merge. Excluded unless requested later: face recognition/identity, cloud camera storage, training a new ML model, arbitrary user Python scripts, licensed film artwork, and a promise of universal zoom/tab shortcuts across every application.

## Interaction contract — proposed defaults, not implemented

| Mode / gesture | Required observation | Effect | Conflict and release rule |
|---|---|---|---|
| Disarmed / preview | App launch, tracking loss, camera retry, or explicit Pause | Overlay and *simulated* intents only | **Always disarmed at launch** in the new release, even if a legacy settings file says enabled. Never infer arming from Save. |
| Pointing (primary) | Calibrated primary hand; index extended, other fingers relaxed/curled; stable for a short configurable dwell | Cursor follows the index fingertip | A non-pointing pose freezes cursor; lost hand releases all buttons. Keep last cursor anchor briefly while entering a deliberate pinch. |
| Left click (primary) | Short thumb–index pinch and clean release while pointing | Exactly one left click | Movement/hold must not also fire a click after drag; cooldown and release-to-rearm. |
| Right click (primary) | Deliberate thumb–middle pinch and release; index pinch absent | Exactly one right click | Cannot coexist with left drag or volume mode; show a distinct preview cue. |
| Drag (primary, opt-in) | Sustained thumb–index pinch plus deliberate movement/hold | Down, movement, up | Off by default initially; release on loss, pause, restart, mode switch, or failed OS input. |
| Volume (secondary) | Secondary hand in a held modifier pose, then vertical motion | Bounded volume change with rate limit | Do not treat ordinary swipes as volume commands; no effect without valid secondary hand and arming. |
| Zoom (paired hands) | Both hands in an armed paired pose; separation changes | App-profile zoom in/out | Dead zone, hysteresis, clamped steps, and release-to-rearm; do not synthesize a click. |
| Switch tabs (paired hands) | Both hands in paired pose; their common center moves laterally while separation stays roughly stable | Next/previous **tab**, via a configurable app shortcut | Suppress if zoom is being recognized. Never confuse tab navigation with existing Alt+Tab window navigation. |
| Cinematic custom gesture | Explicitly selected template or user-authored sequence of poses and motions | Preview-only until validated and bound | Conflict detector, start/finish cue, timeout, cancellation, cooldown, allowlisted actions, no executable user code. |

The exact secondary modifier pose and thresholds are provisional. Tune them from Eli's real camera footage rather than treating these prose defaults as empirically validated.
